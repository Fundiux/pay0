# Signed Sentinel trust and sink IaC preparation

2026-10-10. Source-only preparation; no Terraform plan/apply, remote change, IAM addition, signing key creation, producer activation or sink activation. The existing activate_sink default remains false. Empty signed trust preserves the previous effective filter text and environment map.

## Contract and routing

signed.tf adds signed_trust_manifest, a typed object with schemaVersion PAY0-SIGNED-TRUST@1 and producers defaulting to an empty list. Nonempty trust serializes only the explicit verifier keys into SIGNED_TRUST_MANIFEST_JSON. There are no optional-field defaults that widen cohorts. Terraform object conversion may discard caller attributes outside the declared type; the explicit serializer guarantees those attributes do not enter the runtime manifest. This is not advertised as raw-input unknown-key rejection.

Validation bounds: eight producers; unique stable publisher identifiers excluding the Sentinel namespace; fixed source project pay-0-system and functionName listUsers; ASCII identifiers; exactly one root; one through100 distinct actors/revisions; one or two keys per producer; globally unique explicit KMS key versions with the verifier's region/path/length contract; algorithm RSA_SIGN_PSS_3072_SHA256; ACTIVE/REVOKED status; public SPKI PEM syntax and lowercase SHA256 fingerprint syntax. The serialized ASCII manifest is bounded to16384 bytes. PEM validation checks syntax only. Runtime createSignedVerifier remains responsible for parsing the public key, RSA3072/exponent65537, DER fingerprint equality, PSS salt32 and signature verification. Terraform creates no keys and receives no private-key material.

A nonempty manifest adds a separate complete signed-schema filter. Each producer's service, configuration name, revision cohort, root and actor cohort come from that same trust object; cohorts are not globally merged. The sink combines the legacy and signed filters with fully parenthesized OR. Each lane keeps its own schema and origin criteria. Root/actor LogEntry context is only a routing hint; it cannot replace the signed tuple or the cryptographic verifier.

When trust is empty, the ternary returns the legacy filter expression verbatim, including its newline layout. No SIGNED_TRUST_MANIFEST_JSON variable is emitted. Existing legacy canaries remain eligible; listUsers is always excluded from the legacy configuration. Service overlap is checked case-insensitively and publisher overlap exactly, matching the receiver contract. Preconditions on both observer and sink reject overlap and filters exceeding20000 characters, including a targeted sink operation that would otherwise bypass observer checks. The existing requirement for a reviewed image and nonempty legacy origins remains; this patch does not introduce a signed-only deployment topology.

[Logging query language](https://docs.cloud.google.com/logging/docs/view/logging-query-language) requires explicit grouping when combining AND/OR. [Logging limits](https://cloud.google.com/logging/quotas) cap sink filters at20000 characters. Cross-variable overlap uses resource preconditions to retain compatibility with the module's Terraform>=1.6 declaration; cross-variable input validation itself was introduced in1.9. [HashiCorp guidance](https://support.hashicorp.com/hc/en-us/articles/43291233547027-Error-Invalid-reference-in-variable-validation-in-Terraform-versions-prior-to-1-9).
